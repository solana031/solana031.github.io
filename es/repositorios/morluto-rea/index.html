Propósito y Visión General

**REA (Reverse Engineer Anything)** es un servidor Model Context Protocol (MCP) y una caja de herramientas diseñada para tender un puente entre los agentes de inteligencia artificial y el análisis de software de bajo nivel. Su propósito principal es permitir que un agente de IA investigue características específicas en aplicaciones sin contar con su código fuente original, explicar su funcionamiento a nivel binario o de código intermedio, recopilar evidencia verificable y ayudar a construir implementaciones equivalentes para nuevos proyectos.

REA funciona conectando agentes a herramientas de inspección especializadas para binarios nativos, aplicaciones basadas en JavaScript y Electron, ensamblados `.NET`, sitios web, volcados de memoria y paquetes de firmware. Todo el análisis se ejecuta localmente en la máquina del usuario, vinculando los resultados con la evidencia recopilada y las limitaciones técnicas encontradas.

Requisitos del Sistema y Configuración Documentada

Para utilizar REA, se requiere cumplir con ciertos requisitos técnicos especificados en la documentación oficial:

- **Node.js**: Versiones 22.x (>=22.19), 24.x (>=24.11) o 26+.

- **Gestor de paquetes**: npm.

- **Dependencias de SO**: En sistemas Linux, el análisis estático de JavaScript/Electron, la ejecución de Ghidra, JADX y herramientas de firmware requieren un comando `ps` compatible con `procps` ubicado en el `PATH` para la verificación de propiedad de procesos.

- **Motores de análisis nativo opcionales**: Para el análisis profundo de binarios nativos, se requiere contar con una instalación existente de Hopper, Ghidra o IDA Pro, o bien utilizar proveedores alternativos estáticos.

### Instalación del Agente y Configuración

La configuración inicial para registrar REA en su agente compatible se realiza mediante el siguiente comando documentado:

npx rea-agents setup

Este comando permite seleccionar los agentes deseados (como Claude Code, Cursor, Gemini CLI, entre otros), revisar los cambios propuestos y añadirlos junto con las instrucciones de flujo de trabajo correspondientes.

Para instalar la interfaz de línea de comandos (CLI) globalmente para su uso directo:

npm install --global rea-agents
rea --help

Uso y Ejemplos Prácticos

Una vez configurado, puede interactuar directamente con su agente o utilizar la CLI de REA. Por ejemplo, para inspeccionar un directorio de una aplicación JavaScript o Electron extraída (o un archivo ASAR), ejecute:

npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

Para mantener actualizada su instalación global de REA junto con sus correcciones y mejoras recientes, utilice:

rea update

Ventajas

- **Automatización impulsada por agentes**: Permite que asistentes de IA analicen comportamientos complejos y busquen patrones en código compilado o empaquetado.

- **Ejecución local**: Todo el análisis de ingeniería inversa se realiza de forma local en el entorno del usuario, preservando el control de los datos.

- **Soporte multiplataforma y multiformato**: Cubre desde binarios nativos ELF/PE/Mach-O, bytecode de EVM, artefactos WASM, bases de datos SQLite, hasta paquetes APK de Android y aplicaciones Flutter.

- **Trazabilidad basada en evidencia**: Cada conclusión generada por REA incluye la evidencia técnica correspondiente y las limitaciones de análisis halladas.

Limitaciones

- **Dependencia de herramientas externas**: El análisis profundo de binarios nativos o de aplicaciones móviles requiere la instalación manual previa de software especializado de terceros (como Hopper, Ghidra, IDA Pro o JADX).

- **Restricciones de licencias comerciales**: REA no incluye ni otorga licencias, claves ni derechos de activación para herramientas comerciales propietarias. El usuario debe obtener y estar autorizado a utilizar legalmente dichas herramientas bajo sus términos aplicables.

- **Restricciones operativas locales**: El análisis de ejecuciones en vivo requiere los permisos de usuario adecuados y está sujeto a restricciones de seguridad del sistema operativo host.

Comparativa Editorial y Alternativas

A diferencia de las herramientas tradicionales de desensamblado estático que operan de manera aislada (como Ghidra o IDA Pro de forma individual), REA actúa como una capa de abstracción y un puente MCP diseñado explícitamente para integrar flujos de trabajo de agentes de IA en el proceso de ingeniería inversa. Otras alternativas incluyen el uso manual de descompiladores o la escritura de scripts personalizados con frameworks como `pwntools` o `rizin`, aunque carecen de la integración nativa con protocolos de contexto de agentes que proporciona REA.

Licencia y Precios

- **Licencia**: El código desarrollado y aportado directamente a REA se distribuye bajo la **Licencia MIT**. Los materiales de terceros conservan sus propios avisos de derechos de autor y licencias originales.

- **Precios**: El paquete `rea-agents` en npm y el código fuente en GitHub son de código abierto y gratuitos. Sin embargo, las herramientas comerciales de análisis de soporte (como IDA Pro o Hopper) requieren licencias independientes de sus respectivos proveedores; no se dispone de información de precios verificados integrados en el paquete oficial de REA.
