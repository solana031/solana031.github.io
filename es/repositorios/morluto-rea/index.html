Propósito y caso de uso concreto

REA (Reverse Engineer Anything) es una plataforma que conecta agentes de inteligencia artificial con herramientas de análisis de software: binarios nativos, aplicaciones JavaScript/Electron, assemblies .NET, APK de Android y sitios web. Su propósito es permitirle a su agente investigar una función de una aplicación sin tener el código fuente, obteniendo pseudocódigo, ensamblaje, módulos y evidencias del análisis.

Caso de uso concreto: usted ve una función en una aplicación de notas (por ejemplo, la búsqueda) que le gustaría replicar en su propio proyecto. Puede pedirle a su agente que investigue esa función con REA, y este devolverá cómo funciona, con evidencias y referencias de código, para que usted pueda reimplementarla.

¿Qué es y cómo funciona?

REA actúa como un puente entre su agente de IA y herramientas de análisis. Funciona de la siguiente manera:

1. Su agente llama a REA a través del protocolo MCP (Model Context Protocol).

2. REA inspecciona el objetivo usando herramientas especializadas: Hopper, Ghidra, IDA o Kuna para binarios nativos; análisis estático de JavaScript para apps Electron; JDK y jadx para APK de Android; un navegador Chrome para sitios web; entre otros.

3. REA devuelve hallazgos con evidencias: pseudocódigo, ensamblaje, cadenas, símbolos, referencias de importación y más.

4. Su agente usa estos resultados para hacer preguntas de seguimiento, explicar el comportamiento o escribir y probar una implementación.

Todo el análisis se ejecuta localmente. REA no sube su aplicación a ningún servidor; los resultados llegan a su agente, y el proveedor del modelo de su agente tiene su propia política de datos.

REA se instala como un paquete npm (`rea-agents`) y se configura con el comando `npx rea-agents setup`. Este comando registra el servidor MCP de REA en su agente e instala las instrucciones de flujo de trabajo correspondientes. Después de configurar, debe reiniciar su agente.

¿Cuándo usarlo?

Casos de uso realistas:

1. **Replicar una función de una aplicación comercial.** Ve una característica en una app que quiere en su producto. Puede pedirle a su agente que la investigue sin tener acceso al código fuente.

2. **Comprender el comportamiento de un binario nativo.** Necesita entender cómo funciona un ejecutable de Windows, Linux o macOS a nivel de ensamblaje, sin poder leer su código C/C++ original.

3. **Analizar una aplicación Electron o JavaScript empaquetada.** Tiene un archivo ASAR o un directorio de aplicación Electron y quiere recuperar módulos, importaciones, rutas IPC y relaciones con complementos nativos.

Lo que necesita

Requisitos documentados:

- **Node.js 22.x (>=22.23.4), 24.x (>=24.22.1) o 26.12.1+.** Node.js 23 y 25 no son compatibles. REA no actualiza Node.js automáticamente; debe instalarlo antes de instalar REA.

- **npm** incluido con Node.js.

- **Herramientas de análisis nativo** (opcional, solo para análisis de binarios): Hopper, Ghidra, IDA o Kuna. REA puede instalar Hopper automáticamente con su aprobación; Ghidra, IDA y Kuna usan sus instalaciones existentes.

- **Para análisis de JavaScript estático:** no se requiere motor de análisis nativo.

- **Para Android:** JDK completo y jadx en headless en Linux/macOS/Windows x64.

- **Para análisis web:** un navegador de la familia Chrome.

- **En Linux:** un `ps` compatible con procps en el PATH de REA para verificar la propiedad de procesos. Si no lo tiene, consulte la guía de instalación en `docs/getting-started/installation.md` bajo "Linux owned-process prerequisite".

Instalación

### Acceso hosted (una vez)

Con Node.js y npm instalados, ejecute:

npx rea-agents setup

Esto configura REA en su agente. Elija sus agentes, revise los cambios propuestos y apruebe. El comando añade el servidor MCP de REA y las instrucciones de flujo de trabajo, con respaldos de configuración existente. Reinicie su agente después.

Los agentes soportados incluyen: Claude Code, Codex, Cursor, Gemini CLI, Grok Build y otros. Para agentes no listados, use el registro MCP manual descrito en la guía de instalación.

### Instalación local (para uso regular del CLI)

Para instalar el comando `rea` de forma global:

npm install --global rea-agents
rea --help

### Actualización

Para una instalación global con npm:

rea update

`rea --update` es un alias para este flujo verificado. Para comandos one-off con npx, use `npx rea-agents@latest` seguido del comando. Con Bun, use `bunx rea-agents@latest`. Las actualizaciones globales con Bun requieren Bun 1.2.17 o posterior.

Primer uso paso a paso

1. **Configure su agente:** ejecute `npx rea-agents setup` desde un directorio de confianza fuera del proyecto objetivo. Siga los prompts para seleccionar agentes y apruebe los cambios.

2. **Reinicie su agente** para que cargue la nueva configuración MCP.

3. **Haga una pregunta a su agente**, por ejemplo:

> Entiende cómo funciona la búsqueda en la app Notes, muéstrame la evidencia y construye una función similar para mi proyecto.

4. **Use el terminal para análisis estático de JavaScript:**

```bash

npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

```

Esto devuelve módulos, importaciones, fronteras de Electron y sus evidencias. Reemplace la ruta con su objetivo.

5. **Para análisis nativo,** configure primero un proveedor. Consulte la guía CLI y Evidencia en `docs/getting-started/cli.md` para seleccionar Hopper, Ghidra, IDA o Kuna.

Errores comunes y cómo solucionarlos

- **"Node.js no compatible":** Verifique su versión con `node --version`. Debe ser 22.x (>=22.23.4), 24.x (>=24.22.1) o 26.12.1+. Actualice Node.js antes de reinstallar REA.

- **"Hopper no se inicia":** REA inicia Hopper cuando una operación lo requiere. En macOS, un primer uso puede pedirle que elija modo demo o active su licencia. Complete ese prompt en la misma sessión antes de su primera operación CLI/MCP. Si el problema persista, consulte `docs/getting-started/installation.md#launcher-paths-and-troubleshooting`.

- **"ps no encontrado en Linux":** Instale un `ps` compatible con procps (por ejemplo, `procps` en Debian/Ubuntu) y asegúrese de que esté en el PATH de REA.

- **"Actualización fallida":** Asegúrese de usar Bun 1.2.17 o posterior si actualiza con Bun. Con npm, use `rea update` o `npx rea-agents@latest setup`.

- **"Error de timeout en Ghidra":** Para binarios grandes, aumente el tiempo de inicio con la variable de entorno `REA_GHIDRA_STARTUP_TIMEOUT_MS`.

Limitaciones

- REA es una herramienta de análisis, no un sustituto del entendimiento humano. Los resultados incluyen incertidumbres y limitaciones que debe revisar.

- El análisis nativo requiere herramientas comerciales o de código abierto instaladas (Hopper, Ghidra, IDA, Kuna). REA no las instala ni actualiza (excepto Hopper con aprobación).

- Algunas capacidades (como análisis de dispositivos Android con adb, análisis de firmware con Binwalk/Unblob, o análisis de paquetes JEB) requieren herramientas suministradas por el usuario.

- El análisis de JavaScript y .NET es estático: no ejecuta la aplicación.

- El análisis runtime (captura de procesos, navegadores) ejecuta el objetivo con permisos de usuario; cada guía describe sus efectos.

- El análisis de binarios offline requiere Linux x64 con pwntools para algunas arquitecturas (ELF32 i386, ARM little-endian, MIPS little/big-endian).

- Los precios verificados de herramientas comerciales (IDA Pro, Hopper, JEB) no están disponibles en este paquete; debe consultar a los vendedores.

Alternativas y comparación

Herramientas bien conocidas con diferencias factuales:

- **Ghidra (NSA, código abierto):** Análisis de binarios nativos con desensamblador y pseudocódigo. Gratuito, pero con curva de aprendizaje pronunciada y necesidad de scripts para automatización. REA puede usar Ghidra como motor subyacente.

- **Hopper (comercial):** Desensamblador y descompilador para macOS, Linux y Windows. Interfaz gráfica, más fácil de usar que Ghidra, pero requiere licencia paga.

- **IDA Pro (comercial):** El estándar de la industria para análisis de binarios, con descompilador Hex-Rays. Muy costoso, curva de aprendizaje empinada.

- **Jadx (código abierto):** Descompilador de APK de Android a Java. REA puede usar jadx como herramienta subyacente para análisis de Android.

- **Frida (código abierto):** Dinámica de instrumentación para binarios. REA puede integrarse con Frida para análisis dinámico.

La diferencia clave: REA no es una herramienta de análisis en sí, sino un coordinador que conecta agentes de IA con múltiples herramientas de análisis, devolviendo resultados estructurados con evidencias.

Preguntas frecuentes (FAQ)

**¿Qué agentes pueden usar REA?**

Cualquier agente que soporte servidores MCP locales. REA configura los agentes soportados (Claude Code, Codex, Cursor, Gemini CLI, Grok Build y otros); otros clientes pueden usar el registro MCP manual.

**¿Necesito un motor de análisis nativo?**

El análisis nativo profundo usa Hopper, Ghidra, IDA o Kuna, según el objetivo y la operación. El análisis estático de JavaScript y .NET funciona sin motor de análisis nativo. La configuración puede instalar Hopper después de su aprobación; Ghidra, IDA y Kuna usan sus instalaciones existentes.

**¿Necesito iniciar Hopper primero?**

REA inicia Hopper cuando una operación lo requiere. En macOS, un primer uso puede pedirle que elija modo demo o active su licencia. Complete ese prompt en la misma sessión antes de su primera operación CLI/MCP o trabajo no supervisado.

**¿REA sube mi aplicación?**

No. REA analiza objetivos localmente. Su agente recibe los resultados de herramienta, y su proveedor de modelo tiene su propia política de datos.

**¿Qué hacer si encuentro un error?**

Actualice primero; una versión reciente puede haberlo arreglado. Para CLI global, use `rea update`. Para npx, use `npx rea-agents@latest setup`. Si el problema persista, abra un issue en https://github.com/morluto/rea/issues con su versión de REA, tipo de objetivo, pasos para reproducir y salida de error.

Evaluación editorial: ¿para quién es y quién debe evitarlo?

REA es para:

- Desarrolladores que quieren replicar funcionalidades de aplicaciones sin tener su código fuente.

- Ingenieros de reversa que necesitan un asistente de IA para navegar grandes conjuntos de binarios.

- Equipo de investigación de seguridad que analiza malware o software propietario.

- Estudiantes de ingeniería inversa que quieren automatizar partes del flujo de trabajo.

REA no es para:

- Quienes buscan una herramienta de análisis "todo en uno" sin entender los motores subyacentes.

- Proyectos que requieren análisis 100% automático sin revisión humana de incertidumbres.

- Quienes no tienen Node.js 22.x+ o no pueden instalar herramientas de análisis nativo (Hopper, Ghidra, etc.).

- Uso ilegal o no autorizado. REA es para investigación legal, educación, interoperabilidad, preservación de software y análisis de software que usted o está autorizado a examinar.

Comandos de referencia

npx rea-agents setup

Configura REA en su agente de IA, registrando el servidor MCP e instalando instrucciones de flujo de trabajo.

npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

Analiza un directorio de aplicación JavaScript/Electron o un archivo ASAR, devolviendo módulos, importaciones y fronteras de Electron con evidencias.

npm install --global rea-agents
rea --help

Instala el comando `rea` globalmente y muestra la ayuda del CLI.

rea update

Actualiza la instalación global de REA a la última versión.

rea environment-build ./session.har ./my-env --name my-env --json

Construye un entorno de RL a partir de una captura de red HAR, exportando un bundle para AgentEnv.

agent-env run ./my-env

Ejecuta el entorno de RL construido con AgentEnv (requiere Docker).
