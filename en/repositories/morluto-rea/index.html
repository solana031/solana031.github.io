Purpose and Concrete Use Case

REA (Reverse Engineer Anything) is a platform that connects AI agents with software analysis tools: native binaries, JavaScript/Electron applications, .NET assemblies, Android APKs, and websites. Its purpose is to enable your agent to investigate a function of an application without having its source code, returning pseudocode, assembly, modules, and analysis evidence.

Concrete use case: you see a feature in a notes app (for example, search) that you want in your own product. You can ask your agent to investigate it with REA, and it will return how the feature works, with evidence and code references, so you can reimplement it.

What It Is and How It Works

REA acts as a bridge between your AI agent and analysis tools. It works as follows:

1. Your agent calls REA through the MCP (Model Context Protocol).

2. REA inspects the target using specialized tools: Hopper, Ghidra, IDA, or Kuna for native binaries; static JavaScript analysis for Electron apps; JDK and jadx for Android APKs; a Chrome-family browser for websites; and others.

3. REA returns findings with evidence: pseudocode, assembly, strings, symbols, import references, and more.

4. Your agent uses these results to ask follow-up questions, explain behavior, or write and test an implementation.

All analysis runs locally. REA does not upload your application to any server; results reach your agent, and your agent's model provider has its own data policy.

REA installs as an npm package (`rea-agents`) and is configured with the command `npx rea-agents setup`. This command registers REA's MCP server with your agent and installs matching workflow instructions. After setup, restart your agent.

When to Use It

Realistic use cases:

1. **Replicating a feature from a commercial application.** You see a feature in an app you want in your product. You can have your agent investigate it without access to the source code.

2. **Understanding the behavior of a native binary.** You need to understand how a Windows, Linux, or macOS executable works at the assembly level, without being able to read its original C/C++ code.

3. **Analyzing a packaged JavaScript/Electron application.** You have an ASAR file or an Electron app directory and want to recover modules, imports, IPC routes, and relationships with native add-ons.

What You Need

Documented requirements:

- **Node.js 22.x (>=22.23.4), 24.x (>=24.22.1), or 26.12.1+.** Node.js 23 and 25 are unsupported. REA does not upgrade Node.js automatically; install it before installing REA.

- **npm** included with Node.js.

- **Native analysis tools** (optional, only for native binary analysis): Hopper, Ghidra, IDA, or Kuna. REA can optionally install Hopper with approval; Ghidra, IDA, and Kuna use your existing installations.

- **For static JavaScript analysis:** no native analysis engine required.

- **For Android:** full JDK and headless jadx on Linux/macOS/Windows x64.

- **For web analysis:** a Chrome-family browser.

- **On Linux:** a procps-compatible `ps` on REA's PATH for process ownership checks. If missing, see the installation guide at `docs/getting-started/installation.md` under "Linux owned-process prerequisite".

Installation

### Hosted Access (One-Time)

With Node.js and npm installed, run:

npx rea-agents setup

This configures REA with your agent. Choose your agents, review the proposed changes, and approve. The command adds REA's MCP server and matching workflow instructions, with backups of existing configuration. Restart your agent afterward.

Supported agents include: Claude Code, Codex, Cursor, Gemini CLI, Grok Build, and others. For unsupported agents, use manual MCP registration described in the installation guide.

### Local Installation (for Regular CLI Use)

To install the `rea` command globally:

npm install --global rea-agents

rea --help

### Updating

For a global npm install:

rea update

`rea --update` is an alias for this verified workflow. For one-off commands with npx, use `npx rea-agents@latest` followed by the command. With Bun, use `bunx rea-agents@latest`. Global updates with Bun require Bun 1.2.17 or later.

First Use Step by Step

1. **Set up your agent:** run `npx rea-agents setup` from a trusted directory outside the target project. Follow prompts to select agents and approve changes.

2. **Restart your agent** to load the new MCP configuration.

3. **Ask your agent a question**, for example:

> Understand how search works in the Notes app, show me the evidence, and build a similar feature for my project.

4. **Use the terminal for static JavaScript analysis:**

bash

npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

This returns modules, imports, Electron boundaries, and their evidence. Replace the path with your target.

5. **For native analysis,** configure a provider first. See the CLI and Evidence guide at `docs/getting-started/cli.md` to select Hopper, Ghidra, IDA, or Kuna.

Common Errors and How to Solve Them

- **"Unsupported Node.js":** Check your version with `node --version`. It must be 22.x (>=22.23.4), 24.x (>=24.22.1), or 26.12.1+. Upgrade Node.js before reinstalling REA.

- **"Hopper won't start":** REA starts Hopper when an operation needs it. On macOS, a first-run dialog may ask you to choose demo mode or activate your license. Complete that prompt in the same user session before your first CLI/MCP operation or unattended job. If the problem persists, see `docs/getting-started/installation.md#launcher-paths-and-troubleshooting`.

- **"ps not found on Linux":** Install a procps-compatible `ps` (e.g., `procps` on Debian/Ubuntu) and ensure it is on REA's PATH.

- **"Update failed":** Ensure you are using Bun 1.2.17 or later if updating with Bun. With npm, use `rea update` or `npx rea-agents@latest setup`.

- **"Ghidra timeout":** For large binaries, raise the startup deadline with the `REA_GHIDRA_STARTUP_TIMEOUT_MS` environment variable.

Limitations

- REA is an analysis tool, not a substitute for human understanding. Results include uncertainties and limitations you must review.

- Native analysis requires installed open-source or commercial tools (Hopper, Ghidra, IDA, Kuna). REA does not install or update them (except Hopper with approval).

- Some capabilities (e.g., Android device analysis with adb, firmware analysis with Binwalk/Unblob, JEB package analysis) require user-supplied tools.

- JavaScript and .NET analysis is static: it does not run the application.

- Runtime analysis (process capture, browsers) runs the target with your user permissions; each guide describes its effects.

- Offline binary analysis requires Linux x64 with pwntools for some architectures (ELF32 i386, ARM little-endian, MIPS little/big-endian).

- Verified pricing for commercial tools (IDA Pro, Hopper, JEB) is not available in this package; consult vendors directly.

Alternatives and Comparison

Well-known tools with factual differences:

- **Ghidra (NSA, open source):** Native binary analysis with disassembler and pseudocode. Free, but has a steep learning curve and requires scripts for automation. REA can use Ghidra as a backend engine.

- **Hopper (commercial):** Disassembler and decompiler for macOS, Linux, and Windows. Graphical interface, easier to use than Ghidra, but requires a paid license.

- **IDA Pro (commercial):** Industry standard for binary analysis, with Hex-Rays decompiler. Very expensive, steep learning curve.

- **Jadx (open source):** Decompiles Android APKs to Java. REA can use jadx as a backend for Android analysis.

- **Frida (open source):** Dynamic instrumentation for binaries. REA can integrate with Frida for dynamic analysis.

The key difference: REA is not an analysis tool per se, but a coordinator that connects AI agents with multiple analysis tools, returning structured results with evidence.

FAQ

**Which agents can use REA?**

Any agent that supports local MCP servers. REA configures supported agents (Claude Code, Codex, Cursor, Gemini CLI, Grok Build, and others); other clients can use manual MCP registration.

**Do I need a native analysis engine?**

Deep native analysis uses Hopper, Ghidra, IDA, or Kuna, depending on the target and operation. Static JavaScript and .NET inspection work without a native analysis engine. Setup can install Hopper after approval; Ghidra, IDA, and Kuna use your existing installations.

**Do I need to start Hopper first?**

REA starts Hopper when an operation needs it. On macOS, a first-run dialog may ask you to choose demo mode or activate your license. Complete that prompt in the same user session before your first CLI/MCP operation or unattended job.

**Does REA upload my app?**

No. REA analyzes targets locally. Your agent receives tool results, and your model provider has its own data policy.

**What should I do if I hit a bug?**

Update first; a recent release may already fix it. For global CLI, use `rea update`. For npx, use `npx rea-agents@latest setup`. If using an agent, complete the setup refresh and restart it. Retry the same task. If the problem persists, open an issue at https://github.com/morluto/rea/issues with your REA version, target type, steps to reproduce, and error output.

Editorial Assessment: Who It Is For and Who Should Skip It

REA is for:

- Developers who want to replicate features from applications without having their source code.

- Reverse engineers who need an AI assistant to navigate large binaries.

- Security research teams analyzing malware or proprietary software.

- Students of reverse engineering who want to automate parts of the workflow.

REA is not for:

- Those seeking an all-in-one analysis tool without understanding the underlying engines.

- Projects requiring 100% automated analysis without human review of uncertainties.

- Those without Node.js 22.x+ or unable to install native analysis tools (Hopper, Ghidra, etc.).

- Illegal or unauthorized use. REA is for lawful research, education, interoperability, software preservation, and analysis of software you own or are authorized to examine.

Reference Commands

npx rea-agents setup

Configures REA with your AI agent, registering the MCP server and installing workflow instructions.

npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json

Analyzes a JavaScript/Electron application directory or ASAR file, returning modules, imports, and Electron boundaries with evidence.

npm install --global rea-agents

rea --help

Installs the `rea` command globally and displays CLI help.

rea update

Updates the global REA installation to the latest version.

rea environment-build ./session.har ./my-env --name my-env --json

Builds an RL environment from a HAR network capture, exporting a bundle for AgentEnv.

agent-env run ./my-env

Runs the RL environment built with AgentEnv (requires Docker).
