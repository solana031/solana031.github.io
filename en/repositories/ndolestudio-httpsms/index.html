httpSMS Guide: Android SMS Gateway via HTTP API

Learn how to setup, self-host, and integrate httpSMS to programmatically send and receive SMS messages using an Android device as a gateway via a simple HTTP API.

Purpose and Overview

httpSMS is a service designed to let users use a physical Android phone as a programmatic SMS Gateway. The project addresses the need to interact with SMS messages via a simple HTTP interface, which is particularly useful in regions where buying virtual phone numbers through traditional commercial platforms is challenging. By making standard HTTP requests, the system triggers the mobile device to send messages, and incoming SMS messages on the phone can be forwarded to a configured webhook endpoint.

Documented Requirements

To self-host the system using Docker and run it locally or on your own server, the following prerequisites are required:

A Firebase project for Cloud Messaging, with web SDK configuration and service account credentials (`firebase-credentials.json` and `google-services.json`).

An SMTP server configuration for email notifications.

Cloudflare Turnstile widgets (site key and secret key) to protect search routes.

Docker and Docker Compose to spin up the complete stack including the Go API, Nuxt/Vuetify web UI, database, and cache.

Installation and Setup

The official repository provides clear instructions for deployment via Docker. The documented steps involve cloning the repository, preparing environment files, and executing the container build:

git clone https://github.com/NdoleStudio/httpsms.git
cp web/.env.docker web/.env
cp api/.env.docker api/.env
docker compose up --build

Additionally, the native Android application (`HttpSms.apk`) must be installed on an Android phone configured with the corresponding Firebase settings.

Usage and Code Example

The API allows programmatic interaction with messages. Below is a documented example in Go showing how to send a text message using official API clients:

client := htpsms.New(htpsms.WithAPIKey(/* API Key from https://httpsms.com/settings */))

client.Messages.Send(context.Background(), &httpsms.MessageSendParams{
    Content: "This is a sample text message",
    From:    "+18005550199",
    To:      "+18005550100",
})

Advantages and Features

- **End-to-End Encryption:** Messages can be encrypted using AES-256 so that keys remain solely on the mobile phone, preventing the server from reading content.

- **Back Pressure:** Allows rate-limiting the outgoing message queue (e.g., 3 messages per minute) to avoid overwhelming the mobile provider or device.

- **Message Expiration:** Timeouts can be set for messages so that send failures or delays trigger expiration alerts.

- **Webhook Integration:** Automatically forwards SMS messages received on the phone to an external server via callback URLs.

Limitations

- Heavily relies on the physical availability, network connection, and power state of a dedicated Android phone.

- Self-hosting requires complex initial configuration steps involving Firebase, SMTP, and Cloudflare Turnstile services.

Editorial Comparison and Alternatives

Compared to centralized commercial SMS gateway platforms (such as Twilio or corporate virtual number providers), httpSMS provides a self-hosted alternative leveraging the user's existing mobile hardware and carrier plan. This removes recurring commercial subscription fees for virtual numbers, while shifting the maintenance of both the server stack and the mobile device to the administrator.
